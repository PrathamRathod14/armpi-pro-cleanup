The problem

Three things make this hard

One camera, two jobs

The only camera sits on the arm. Raised, it looks ahead to find objects; lowered, it looks at the gripper to line up. It can never do both at once.

No distance sensor

Nothing measures how far away an object is. The robot reads it from the picture: a near object looks bigger and sits lower in the frame.

Moved objects stay in view

Without a box, a placed object is still on the floor and still red. To the camera it looks exactly like one that has not been picked up yet.

What the robot has

A camera that moves with the arm, and wheels that move any way

One USB colour camera, on the arm

Points wherever the arm points. It sees colours well, but has no depth, so all distance comes from the picture.

Six bus servos with position feedback

Base, shoulder, elbow, wrist, wrist turn and gripper. Each reports where it is, so arm positions can be taught by hand and replayed exactly.

Mecanum wheels

Forward, backward, sideways and turning on the spot. Sideways moves make the final line-up possible without turning.

Raspberry Pi 4 with ROS Melodic

Runs the camera, the servos and the program. Also reads the battery voltage. No lidar, no distance sensor, no motion sensor.

So the plan uses the arm twice: raised to find and drive to an object, lowered to line it up between the fingers. Arm positions are taught once by hand instead of calculated.

Doing one thing at a time

The robot is always in exactly one state

The wheels and the arm never move at the same time.

The robot always stops driving before the arm moves, and the arm finishes before the wheels move again. That makes every step easy to watch and easy to stop with Ctrl+C, and a swinging arm never meets a moving floor.

If the object leaves the picture for 2 seconds while driving, the robot stops and searches again. It never keeps driving toward where it thinks the object was.

The camera picture in the raised pose. Off centre: turn toward it. In the band: drive forward. Lower edge on the dashed line: stop and look down.

Working with the robot

Habits that save time and the robot

Clear floor, hand on Ctrl+C

The robot cannot see obstacles. Test in an open area about 1–2 m across, and stop it the moment it does something unexpected.

Change one setting at a time

Run, note what went wrong, change one value, run again. Two changes at once hide which one helped.

Re-check colours when the light changes

Colour detection depends on lighting. A different room or time of day means repeating the task 3 check.

Mind the camera cable

If the camera picture freezes after arm moves, the cable has probably been tugged. Reseat it, leave slack, and reboot.

Halt before switching off

Run sudo halt and wait a few seconds before the power switch, so the SD card is not damaged.

Keep the hotspot steady

Turn on the phone hotspot before the robot. If the robot misses it, it falls back to its own Wi-Fi after about 30 seconds.
